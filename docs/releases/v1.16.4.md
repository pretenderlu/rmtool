# rmtool v1.16.4

## 中文

- **修复恢复出厂后的残缺状态：** 新增“清理不完整状态”检测，可处理恢复出厂或中断安装后残留的 rmtool 共享 XOVI 半成品。
- **严格归属验证：** 只有在核心文件或 drop-in 指纹、root 权限、父路径、挂载边界和外部启动配置全部确认安全时才允许清理；未知文件、符号链接、双布局、Vellum/AppLoad/XOVI 或其他第三方配置都会阻止操作。
- **限定清理范围：** 只删除 rmtool 共享基座、受校验的 drop-in 和紧急停用标记，不删除微信读书、KOReader、字体、书籍或其他 `/data/rmtool` 内容。
- **清理后可重新安装：** 清理完成后插件状态恢复为“未安装”，用户可以重新检测并安装当前固件对应的插件；操作完成后需手动重启设备。

本功能已完成模拟设备、回滚路径和清理脚本校验，但尚未在真实设备执行删除测试。使用前请确保设备具备官方恢复路径。

Windows x64 与 macOS ARM64 应用安装包从 GitHub Releases 提供。

## English

- **Factory-reset residue recovery:** Added a **Cleanup incomplete state** check for partial rmtool shared-XOVI installations left by a factory reset or interrupted setup.
- **Strict ownership proof:** Cleanup is enabled only when core-file or drop-in fingerprints, root ownership, parent paths, mount boundaries, and external startup configuration are verified. Unknown files, symlinks, double layouts, Vellum/AppLoad/XOVI, and foreign configuration block the operation.
- **Bounded cleanup:** Only the rmtool shared base, verified drop-in, and emergency-disable markers are removed. WeRead, KOReader, fonts, books, and other `/data/rmtool` content are never touched.
- **Ready for reinstall:** After cleanup, plugin state returns to **Not installed**, allowing detection and installation of the package for the current firmware. Restart the device manually afterward.

The feature passed simulated-device, rollback-path, and cleanup-script validation, but no real-device deletion test was performed before release. Ensure an official recovery path is available before using it.

Windows x64 and macOS ARM64 application packages are provided through GitHub Releases.
